# 上电、校准与验收

## A. 断电检查

1. 钢琴、ESP32 和 5 V 灯带电源全部拔掉。
2. 万用表通断档确认：灯带 `5V-GND` 不蜂鸣；ESP32 GND、74AHCT125 GND、灯带 GND 互通；DATA 与 CLOCK 不互通。
3. 确认电解电容负条纹接 GND，保险丝串在 5 V 正极，灯带箭头从输入端指向末端。
4. 首次上电前不连接钢琴 USB。

## B. 分级上电

1. 只给 ESP32 的 UART 口供电，串口应出现启动日志，手机能看到 `NoteFall-88` 热点。
2. 手机连接该热点（密码 `notefall88`），打开 `http://192.168.4.1`；状态应为“ESP 已连接、钢琴未连接”。
3. 断电，接入 74AHCT125 与灯带，再接 5 V/5 A 电源。网页依次点 A0、C4、C8 测试键；每次只应亮一处黄色灯。
4. 如果方向相反，在设置中打开“灯带反向”；若三点整体平移，用像素偏移调整。设置保存在 ESP32，重启后仍有效。
5. 最后连接 PX-S7000。钢琴的方形 `USB TO HOST` → 打印机线 → OTG Y 线 USB-A 母口；Y 线 Micro-USB 公头 → 开发板 `USB/OTG` 口；Y 线供电支路 → 普通 5 V USB 充电器。开发板 `UART` 口仅负责刷机和日志。

## C. 功能验收

| 测试 | 方法 | 通过标准 |
|---|---|---|
| USB 枚举 | 开关钢琴 5 次 | 每次网页在 3 s 内显示“钢琴 USB 已连接”，无重启 |
| 全键映射 | 从 A0 到 C8 半音阶弹 88 键 | 每键横向位置唯一；最大视觉偏差不超过半个 LED 间距 |
| 和弦 | 同时按 10 个键，重复 20 次 | 无漏键、无卡灯；松键后状态清除 |
| 等待练习 | 导入包含和弦的 MIDI，选择等待模式 | 只有完成当前和弦后才进入下一组 |
| 跟随伴奏 | 选择“跟随我”和右手，故意以 50%、100%、约 140% 的个人速度逐组弹奏 | 左手由 PX-S7000 音源播放；下一目标从实际命中时刻按谱面间隔推进，不突然追赶 |
| 跟随循环 | A–B 内包含左右手交替、长音和重复同音，连续 5 轮 | 跨 B 后回到 A；同音重触发无意外截断，循环间无挂音 |
| MIDI OUT 安全 | 伴奏长音期间关闭网页、拔手机 Wi-Fi、按“全部熄灭”各一次 | 每次钢琴伴奏在 1 s 内停止，无持续挂音；重新连接后可继续练习 |
| 多页面互斥 | 手机和平板同时打开网页并先后启动跟随模式 | 第一台持有伴奏输出，第二台明确显示“被其他页面占用”且不重复发声；第一台关闭后第二台可接管 |
| MusicXML/MXL | 分别导入同一首 `.musicxml` 与 `.mxl` | 五线谱、音符数、时长和目标灯一致；谱面可切回瀑布流 |
| 乐谱导航 | 导入含反复、第一/第二结尾、D.C. al Fine、D.S. al Coda 的固定样例 | 目标/判分按真实演奏顺序，OSMD 光标回到正确书写小节；跳转只执行一次且能终止 |
| 本地曲库 | 重复导入同一文件，再新建文件夹并移动乐谱 | 内容哈希去重，只保留一份；刷新页面后仍存在 |
| 曲库备份 | 导出 JSON，在空浏览器配置中恢复 | 文件夹、原始乐谱、名称和统计恢复；篡改内容后校验失败且不产生半恢复数据 |
| 演奏录制 | 录制力度、重叠同音和延音踏板后导出 MIDI | 回放音高/通道/力度正确；踏板松开前的音符持续保留 |
| 长时间等待 | 在一个目标和弦停留 30 s | 目标灯全程保持；关闭网页后 3 s 内熄灭 |
| 实时练习 | 选择实时模式和 50/100/150% 速度 | 瀑布、目标灯、计时一致，无持续漂移 |
| 左右手 | 分别选择双手、左手、右手 | 未选声部不进入实体目标或判分；屏幕仅低亮度保留 |
| 移调 | 对同一 MIDI/MusicXML 分别选择 -12、0、+2、+12 | 五线谱/瀑布流/目标灯同步变化；恢复 0 后与原谱一致；曲库原文件哈希不变 |
| A–B 循环 | 设置 A=60 s、B=90 s，连续播放两轮 | 到 B 自动回到 A；没有越界目标，累计成绩不清零 |
| 实时判分 | 在目标前后故意制造正确、错键和漏键 | 三类计数分别增加；重复按同一正确音不重复计分 |
| 练习洞察 | 实时模式分别稳定提前约 100 ms、稳定延后约 100 ms，再弹一组力度由弱到强的音 | 拍点分别显示偏早/偏晚；平均与 P95 非负；力度均值和波动随输入改变；重复正确音不污染统计 |
| 练习历史 | 完成一次练习，刷新网页，再改变速度和循环完成第二次并导出 JSON | 两次记录均存在且按新到旧排列；模式/速度/循环上下文正确；JSON 不包含 Wi-Fi 凭据或乐谱原文件 |
| 断网安全 | 练习中关闭手机 Wi-Fi | 3 s 内目标灯自动熄灭；钢琴仍可正常发声 |
| 断电恢复 | 重启 ESP32 | 亮度、反向和偏移保持 |
| 逐键微调 | 将 C4 修正 +1、A0 修正 -1 后重启 | 两键各移动一枚灯珠，其余键不变；网页重新打开仍显示修正值 |
| 30 min 温升 | 最亮允许值下运行混合图案 | 灯带、接头、线束任何点低于 55°C，无异味或变色 |
| 机械 | 全键强奏、移动谱架和轻拉线缆 | 竖直灯带不触键、不位移、不产生异响；灯光能落到对应琴键 |

完成 USB 枚举和和弦测试后打开“灯带校准 → 设备诊断”：VID/PID、IN 端点和 OUT 端点应为非零值；输入包数应随弹奏增加，OUT 发送数应随跟随伴奏增加，排程最终回到 0；PSRAM 总量应约为 8 MiB，两组 `丢包 / 错误` 必须保持 `0 / 0`。若 OUT 显示“设备未提供”，先保存 VID/PID、完整串口日志和端点截图，再使用无伴奏跟随，不更换为 SPI USB Host 模块。若丢包增加，先保存页面截图和串口日志，不要通过增大队列掩盖 USB/任务阻塞问题。

发布构建还必须执行 `platformio run -d firmware -t buildfs`，并用 `mklittlefs -l` 读取生成镜像确认其中同时存在 `index.html` 和全部 `.gz` 资源。PlatformIO 旧打包器曾出现命令返回成功但单文件加入失败，不能只看最后一行 `SUCCESS`。

出现过热、闪烁、随机重启、USB 反复掉线或 5V-GND 短路时立即断电，不通过增加亮度或换大保险丝掩盖故障。

## D. 延迟记录

网页显示的 WebSocket 往返时间只影响屏幕与目标下发，不影响“琴键 → ESP32”链路；后者是本地 USB。验收时录制 120 fps 手机视频，同时拍到手指、灯和屏幕，抽查 20 次按键。目标为按键反馈灯中位数 <25 ms、95 百分位 <40 ms；超过时先排除手机省电和 Wi-Fi 拥堵，再检查固件串口日志。
