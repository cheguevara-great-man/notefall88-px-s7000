# 上电、校准与验收

## A. 断电检查

1. 钢琴、ESP32 和 5 V 灯带电源全部拔掉。
2. 万用表通断档确认：灯带 `5V-GND` 不蜂鸣；ESP32 GND、74AHCT125 GND、灯带 GND 互通；DATA 与 CLOCK 不互通。
3. 确认首尾两个电解电容负条纹接 GND，3 A 保险丝串在 5 V 正极且距入口不超过 100 mm，灯带箭头从输入端指向末端。
4. 按 `docs/harness.csv` 逐线蜂鸣：Micro-Fit 1/2/3/4 必须依次为红 +5V、黑 GND、绿 DATA、蓝 CLOCK；XT30 只含红 +5V 和黑 GND；供电侧均无裸露带电公针。
5. 不接任何模块，在 DC5521 输入端用实验限流源或带 3 A 保险丝的成品电源上电，所有 +5V 节点必须为 `4.75–5.25 V` 且极性正确，然后断电。
6. 首次上电前不连接钢琴 USB。

## B. 分级上电

1. 首次刷机可只给 ESP32 的 UART 口供电，串口应出现启动日志，手机能看到 `NoteFall-88` 热点；完成后拔掉 UART 线。
2. 手机连接该热点（密码 `notefall88`），打开 `http://192.168.4.1`；状态应为“ESP 已连接、钢琴未连接”。
3. 断电，接入 74AHCT125、灯带和 H5→USB-to-UART 供电线，原生 USB/OTG 口暂不接钢琴，再接整机唯一的 5 V/5 A 电源。先以 10% 亮度点亮，网页依次点 A0、C4、C8；每次只应亮一处黄色灯。
4. 如果方向相反，在设置中打开“灯带反向”；若三点整体平移，用像素偏移调整。设置保存在 ESP32，重启后仍有效。
5. 最后连接 PX-S7000。钢琴的方形 `USB TO HOST` → 打印机线 → OTG Y 线 USB-A 母口；Y 线 Micro-USB 公头 → 开发板 `USB/OTG` 口。H5 始终插在开发板 `UART/USB-to-UART` 口给板子供电；H7 插入 Y 线第 3 个 Micro-USB 口给钢琴 USB 设备侧提供 VBUS。H5、H7 必须来自同一保险后的 5V 电源，不能用两只互不相关的适配器。

## C. 功能验收

| 测试 | 方法 | 通过标准 |
|---|---|---|
| USB 枚举 | 开关钢琴 5 次 | 每次网页在 3 s 内显示“钢琴 USB 已连接”，无重启 |
| 全键映射 | 从 A0 到 C8 半音阶弹 88 键 | 每键横向位置唯一；最大视觉偏差不超过半个 LED 间距 |
| 和弦 | 同时按 10 个键，重复 20 次 | 无漏键、无卡灯；松键后状态清除 |
| 等待练习 | 导入包含和弦的 MIDI，选择等待模式 | 只有完成当前和弦后才进入下一组 |
| 跟随伴奏 | 选择“跟随我”和右手，故意以 50%、100%、约 140% 的个人速度逐组弹奏 | 左手由 PX-S7000 音源播放；下一目标从实际命中时刻按谱面间隔推进，不突然追赶 |
| 跟随循环 | A–B 内包含左右手交替、长音和重复同音，连续 5 轮 | 跨 B 后回到 A；同音重触发无意外截断，循环间无挂音 |
| MIDI OUT 安全 | 伴奏长音期间关闭网页、拔手机 Wi-Fi、按“全部熄灭”各一次 | 每次钢琴伴奏在 1 s 内停止，无持续挂音；重新连接后可继续练习 |

| 演奏录制 | 录制力度、重叠同音和延音踏板后导出 MIDI | 回放音高/通道/力度正确；踏板松开前的音符持续保留 |
| 长时间等待 | 在一个目标和弦停留 30 s | 目标灯全程保持；关闭网页后 3 s 内熄灭 |
| 实时练习 | 选择实时模式和 50/100/150% 速度 | 瀑布、目标灯、计时一致，无持续漂移 |

| 更新失败安全 | 依次上传过小文件、错误扩展名、超过分区上限和损坏固件 `.bin` | 浏览器前三者不发送；固件端拒绝损坏镜像且不报告成功；伴奏/灯光先安全停止，原固件重启后仍可启动 |

| 练习历史 | 完成一次练习，刷新网页，再改变速度和循环完成第二次并导出 JSON | 两次记录均存在且按新到旧排列；模式/速度/循环上下文正确；JSON 不包含 Wi-Fi 凭据或乐谱原文件 |
| 自适应建议 | 在全曲不同位置制造一组集中错漏，并让一只手错误率明显更高 | 建议锁定包含错漏簇的 A–B 段和较弱手；显示证据量/置信度；一键应用后模式、声部、速度和循环控件完全一致 |
| 断网安全 | 练习中关闭手机 Wi-Fi | 3 s 内目标灯自动熄灭；钢琴仍可正常发声 |
| 断电恢复 | 重启 ESP32 | 亮度、反向和偏移保持 |
| 逐键微调 | 将 C4 修正 +1、A0 修正 -1 后重启 | 两键各移动一枚灯珠，其余键不变；网页重新打开仍显示修正值 |
| 校准存储诊断 | 重启后查看“设备诊断 → 校准存储 NVS”，再确认逐键修正仍存在 | 显示“正常”且修正保持；若显示异常，停止校准并先重刷/检查 Flash，不误报已保存 |
| 复位原因诊断 | 正常断电重启一次，再在固件亮度上限连续点亮并强奏 | 正常启动显示 `power-on`；测试中不得自行重启，之后不得出现 `brownout`、`panic` 或 `watchdog` |
| USB→灯内部延迟 | 连续弹奏单音、和弦与快速音阶至少 200 个 Note On/Off，读取设备诊断 | 样本持续增长、最大值 `<10 ms`、丢包/错误为 0；它只覆盖 USB 回调到 SPI 完成，仍需视频测端到端 |
| 30 min 温升 | 最亮允许值下运行混合图案 | 灯带、接头、线束任何点低于 55°C，无异味或变色 |
| 供电压降 | 最亮允许值运行 10 min，分别测电源入口、灯带首端和远端 | 入口不低于4.75 V；任一灯带端相对入口下降不超过0.25 V；无肉眼可见首尾色差 |
| 保险保护 | 断电取下3 A保险丝再尝试上电 | 灯带、ESP32和OTG支路均不得上电；装回同规格保险丝后恢复 |
| 机械 | 全键强奏、移动谱架和轻拉线缆 | 竖直灯带不触键、不位移、不产生异响；灯光能落到对应琴键 |

完成 USB 枚举和和弦测试后打开“灯带校准 → 设备诊断”：VID/PID、IN 端点和 OUT 端点应为非零值；输入包数应随弹奏增加，OUT 发送数应随跟随伴奏增加，排程最终回到 0；PSRAM 总量应约为 8 MiB，两组 `丢包 / 错误` 必须保持 `0 / 0`。正常使用时 ESP/浏览器两侧“拒绝消息”都应保持 0；只有故障注入或旧页面连接时才允许增加。USB→灯内部延迟样本应随按键增长且最大值低于 10 ms。若 OUT 显示“设备未提供”，先保存 VID/PID、完整串口日志和端点截图，再使用无伴奏跟随，不更换为 SPI USB Host 模块。若丢包或内部延迟增加，先保存页面截图和串口日志，不要通过增大队列掩盖 USB/任务阻塞问题。

发布构建还必须执行 `platformio run -d firmware -t buildfs`，并用 `mklittlefs -l` 读取生成镜像确认其中同时存在 `index.html` 和全部 `.gz` 资源。PlatformIO 旧打包器曾出现命令返回成功但单文件加入失败，不能只看最后一行 `SUCCESS`。

出现过热、闪烁、随机重启、USB 反复掉线或 5V-GND 短路时立即断电，不通过增加亮度或换大保险丝掩盖故障。

## D. 延迟记录

网页显示的 WebSocket 往返时间只影响屏幕与目标下发，不影响“琴键 → ESP32”链路；后者是本地 USB。验收时录制 120 fps 手机视频，同时拍到手指、灯和屏幕，抽查 20 次按键。目标为按键反馈灯中位数 <25 ms、95 百分位 <40 ms；超过时先排除手机省电和 Wi-Fi 拥堵，再检查固件串口日志。
