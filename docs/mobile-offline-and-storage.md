# 手机/平板离线与本地数据

## 当前可证明的离线方式

NoteFall Core 的完整 HTML、压缩 JavaScript、CSS 和乐谱渲染资源都位于 ESP32 LittleFS。手机连接 `NoteFall-88` 热点后访问 `http://192.168.4.1`，即使没有互联网也能重新加载页面；这不是依赖云端缓存的“离线模式”，而是设备本身提供网页。

不要在当前部署上承诺 Service Worker/PWA 离线缓存。Service Worker 通常只允许 HTTPS 或 `localhost` 安全上下文，而 ESP 热点使用局域网 HTTP 地址。即使某个浏览器允许“添加到主屏幕”，也不能据此推断它已安装可靠的离线 Service Worker。未来若另行发布 HTTPS Studio PWA，还必须解决 HTTPS 页面访问本地 `ws://` 设备产生的混合内容限制；可选方向是可信 WSS、本地原生壳或明确的设备桥接，不应靠浏览器偶然放行。

## 哪些数据保存在手机

- 曲库：当前页面 origin 下的 IndexedDB；
- 练习历史：独立 IndexedDB，最多 500 次，每次最多 20,000 个判定事件；
- 常用练习选项：localStorage；
- ESP 的亮度、灯位和 Wi-Fi 配置：设备 NVS，不在浏览器备份中。

浏览器数据按 origin 隔离。`http://192.168.4.1`、开发电脑的 `http://localhost` 和未来 HTTPS Studio 是三份不同数据，不能假定自动共享。清除站点数据、卸载浏览器、私密模式结束或系统存储压力都可能删除非持久数据。

## 页面提供的保护

“我的曲库”显示浏览器报告的已用空间、配额和持久化状态。“保护本地数据”只在用户点击后调用 Storage Persistence API：

- 获准后显示“已获持久存储保护”；
- 浏览器拒绝或 HTTP 环境不支持时，页面继续工作并提示保留备份；
- 配额不足、私密模式或站点存储被禁用时，曲库和练习历史显示可执行的中文错误，不把失败伪装成保存成功。

持久化不是备份。曲库使用“导出曲库备份/恢复曲库备份”，练习历史在练习选项中单独导出 JSON。两个入口故意使用不同名称，因为当前不存在一个已经验证可原子恢复两套数据库与 ESP NVS 的全系统备份。

## 实机验收

至少在计划长期使用的 iOS/Android 浏览器各执行一次：

1. 连接 `NoteFall-88`，打开页面并导入一首测试乐谱；
2. 打开“我的曲库”，记录容量、持久化状态和是否获准；
3. 断开互联网但保持 ESP 热点，强制关闭浏览器后重新打开页面；
4. 确认页面资源、曲库和练习功能仍可用；
5. 导出曲库备份，删除测试乐谱，再恢复并核对文件 SHA-256；
6. 在浏览器测试环境模拟配额不足，确认页面提示备份与清理建议且已有数据不被删除。

若浏览器把无互联网热点自动切回蜂窝网络，应关闭该网络的“自动切换/智能网络”或明确选择继续连接；这是手机联网策略，不是 ESP USB 或灯带故障。
