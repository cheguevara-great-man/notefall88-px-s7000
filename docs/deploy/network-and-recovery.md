# 家庭网络、救援热点与防变砖机制

NoteFall 88 正常使用时优先连接已保存的 2.4 GHz 家庭 Wi-Fi。凭据保存在 ESP32 的 NVS 中，断电、普通固件 OTA 和网页更新都不会清除；平板也只需让 Android 保存一次家庭 Wi-Fi 密码。练琴时直接打开已安装的 **NoteFall Studio**：Android 原生层会在局域网内发现 ESP32，并在断线或 DHCP 地址变化后重新发现和连接，不要求用户记 IP。

## 永久可达的两条网络路径

- **日常路径**：ESP32 自动连接家庭 2.4 GHz Wi-Fi；平板可以连接同一路由器的 2.4 GHz 或 5 GHz。Studio 用 UDP 32188 自动发现设备；固件关闭 Wi-Fi 省电并启用自动重连，断线后每 10 秒主动重试。
- **救援路径**：`NoteFall-88` 热点始终开启，不因家庭 Wi-Fi 成功而关闭。家庭路由器故障、密码变更或 mDNS 不可用时，平板连接该热点并打开 `http://192.168.4.1/recovery`。

设备管理密码与家庭 Wi-Fi 密码不是一回事。客户端成功解锁后保存的是随机控制令牌，不保存明文管理密码；令牌和 ESP32 重启前后一致，因此同一客户端不需要每次重新输入。原生 Studio 只在设备明确报告仍使用出厂管理密码时自动完成首次换取令牌；修改设备管理密码会立即撤销旧令牌。

小米 Pad 7 Ultra 的 Android 16 实机已经完成以下验收：首次授予“附近设备”权限后，Studio 能发现 `192.168.1.7` 的实机、建立 WebSocket、在 ESP32 重启后自动恢复连接，并继续使用已保存的随机令牌。`notefall.local` 仍由固件发布，但在该平板和当前路由器组合上不能可靠解析，因此它只是可选入口，不是日常方案的单点依赖。

## OTA 失败时的确定行为

| 故障 | 设备行为 |
|---|---|
| 上传途中断网、浏览器关闭或断电 | 未完成镜像不会被设为启动槽；继续运行原固件 |
| 上传了非 NoteFall 固件 | 项目标识检查失败，拒绝切换启动槽 |
| 新固件启动崩溃或被看门狗复位 | ESP-IDF bootloader 自动回滚到上一 OTA 槽 |
| 新固件能启动但网页/网络不可达 | 90 秒内收不到真实 HTTP/WebSocket 健康访问，主动回滚 |
| 新固件可达但存储、灯带、USB Host 或实时任务自检失败 | 不确认新槽，90 秒后回滚 |
| LittleFS 普通网页损坏 | 固件内置 `/recovery`，仍可重刷网页或固件 |
| 家庭 Wi-Fi 不可用 | 永久 `NoteFall-88` 热点仍可进入救援页 |

新固件只有在启动至少 10 秒、内部关键模块健康，并且平板或浏览器确实访问成功后，才调用 `esp_ota_mark_app_valid_cancel_rollback()`。在此之前它保持 `ESP_OTA_IMG_PENDING_VERIFY`。没有得到确认的版本在 90 秒后调用 `esp_ota_mark_app_invalid_rollback_and_reboot()`。

## 日常使用

1. 平板保持连接家庭 Wi-Fi。
2. 打开已安装的 NoteFall Studio；首次出现“附近设备”权限时允许一次，以后无需重复操作。
3. 临时使用浏览器 Core 时可打开设备设置中显示的家庭 IP；当前实机为 `http://192.168.1.7`，但 DHCP 地址以后可能变化。若路由器支持 mDNS，也可尝试 `http://notefall.local`。
4. 家庭网络或自动发现不可用时，切换到 `NoteFall-88` 并访问 `http://192.168.4.1/recovery`。这一入口不依赖家庭路由器、mDNS 或 LittleFS。

原生 App 使用独立的 `https://studio.notefall` 内部 origin，并禁用 PWA Service Worker 注册，避免 APK 更新后继续运行缓存中的旧脚本；浏览器 PWA 仍保留离线缓存。该 origin 只存在于 App 内，不是需要在浏览器中访问的网站。

不要擦除 NVS 或反复刷 factory 镜像；这两种操作才会清除家庭 Wi-Fi、控制令牌和 88 键校准。普通双槽 OTA 不会清除这些数据。
