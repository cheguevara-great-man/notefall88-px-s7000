# ADR-004：Studio 采用混合原生容器与 GPU Web 渲染

- 状态：已接受
- 日期：2026-08-09

## 决策

NoteFall Studio 同时交付可安装 PWA 和 Capacitor Android/iOS 应用。移动应用是原生安装包与原生生命周期容器，MusicXML/练习引擎和协议继续共享 TypeScript；OSMD 谱面保留专用 WebView。Android 已实现硬件加速原生瀑布流 View：乐谱与键盘几何只在变化时跨桥传送，播放时钟低频校正后由原生视图按系统单调时钟逐帧绘制，不传像素帧。iOS 当前使用 Canvas/WebGL 回退，保留相同接口等待 Xcode 环境实现对应原生视图。

这不是把远程网站塞进壳里：Studio 的全部前端资源随应用打包、可离线启动，并通过协议 v6 连接 ESP32 Core。Core 内置网页继续作为零安装救援入口。

## 为什么不立即整套真原生重写

SwiftUI/Compose/Flutter 直接绘制的理论上限更高，但 OSMD 的 SVG/DOM 谱面仍需 WebView 或重新实现专业排版。实体灯的实时决策与 SPI 输出在 ESP32 内完成，不依赖 UI 调度。需要重写的是呈现和交互层，不是 MusicXML、练习、评分、曲库、协议或固件；因此瀑布流原生化是局部、可控的升级，不应被描述成“整套工程重写”。

## 不是永久锁定

Canvas/WebGL 基线和 Android 原生版本必须在相同数据集上通过以下门禁：

- 典型双手密集谱在 60 Hz 屏幕持续低于 55 FPS；
- 触控到画面反馈的 P95 超过 50 ms；
- 连续练习 60 分钟发生 WebView 回收、音画时序漂移或不可恢复断连；
- 局域网、文件或后台恢复无法由受限原生桥接可靠解决。

因此，本决策是“共享引擎 + 混合谱面 + 原生 GPU 瀑布流”，而不是声称 WebView 与真原生完全相同。
